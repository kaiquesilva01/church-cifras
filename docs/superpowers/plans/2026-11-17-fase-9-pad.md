# Fase 9 — Pad ambiente: Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Botão **Pad** na cifra que toca o pad ambiente do tom exibido (início original + loop de 16 compassos), com volume, fades, transição de tom dentro do repertório e tela acesa enquanto toca.

**Architecture:** Um `PadProvider` leve (no bundle principal, ao lado do `ActiveSetlistProvider`) guarda estado e regras de "continua/para"; o motor Web Audio e o carregador de buffers são importados sob demanda no primeiro toque. Os 12 loops AAC (~1 MB cada) ficam no Storage em `pads/` e passam pelo cache do PWA. O viewer só informa o tom exibido (`follow`) e pede pré-carga.

**Tech Stack:** React 19 + TS strict, Web Audio API, Screen Wake Lock API, Firebase Storage (`getBlob` via `CatalogApi.getPdfBytes`), Workbox, vitest, Playwright, Node + ffmpeg (scripts locais).

**Spec:** [docs/superpowers/specs/2026-11-17-pad-design.md](../specs/2026-11-17-pad-design.md) (lê-lo junto; este plano só fixa as decisões que o spec deixa abertas).

**Divisão de PRs (todos para `develop`, revisão do `code-reviewer`, merge só do orquestrador):** PR 1 = Tasks 0–4 (infra e scripts) · PR 2 = Tasks 5–9 (motor e provider) · PR 3 = Tasks 10–13 (UI, E2E, docs). Agentes: Tasks 1, 4 → `backend-dev`; Tasks 2, 3, 5–12 → `frontend-dev`; Task 12 também `qa`. Sonnet 5.5, effort medium.

## Global Constraints

- Fades (spec §5.3): **saída 3 s · transição cruzada 4 s**, curvas de potência igual; **sem fade de entrada do app**, só rampa de **~50 ms** (o crescimento de ~3,5 s do arquivo é a entrada); mudança de volume suavizada em **~30 ms**.
- Volume 0–1 com curva perceptiva `ganho = v²`, padrão **0,6**, lembrado por aparelho em `localStorage` (`cifras.pad.volume`), sempre em `try/catch`.
- Tom menor usa o pad da **mesma nota** (Am → A); bemóis mapeados para sustenidos (Bb → A#). Pad segue o **tom salvo exibido** (`selected`), nunca a prévia do painel.
- Regra de parar (§5.2): fora de repertório, só vale na própria cifra; em repertório, vale na cifra com `?repertorio=<mesmo id>` e na tela `/repertorios/<mesmo id>`; qualquer outra rota → fade-out e para.
- Memória: no máximo **2 buffers decodificados** vivos; no máximo 2 vozes tocando (a antiga sai ao fim da transição).
- Nada de áudio no bundle inicial (`import()` dinâmico do motor e do loader). `AudioContext` nasce e `resume()` é chamado **de forma síncrona dentro do toque** no botão.
- Storage `pads/{version}/{fileName}` (hoje `pads/v1/DS04-C.m4a`; a versão vem de `padManifest.json` e muda quando os loops são regerados, porque o cache é de 1 ano): leitura para autenticado, escrita negada a todos. **Nunca commitar áudio** (`*.m4a` entra no `.gitignore`; sources/loops ficam em `fixtures/private/pads/`).
- Texto de UI em pt-BR; identificadores em inglês; TS `strict`; Conventional Commits em inglês; branch `feat/pad` a partir de `origin/develop`.

## Review Focus

Entradas que o spec implica e nenhuma task testaria sozinha; cada linha tem o teste na task dona.

1. **iOS exige o `AudioContext` criado no toque:** se for criado depois de um `await`, o som não sai. → Task 9 (fábrica padrão).
2. **Navegar no repertório:** enquanto as arrangements da próxima cifra carregam, `selected` é `null`; isso **não** pode parar nem trocar o pad. → Task 9 (`follow(null)`) e Task 10.
3. **Próxima, próxima, próxima rápido** (A→B→C antes de B carregar): só o último tom toca, sem vozes velhas sobrando. → Task 6.
4. **Tocar em Pad enquanto ainda carrega:** cancela, e o som nunca começa depois. → Task 9.
5. **Sair da conta / desmontar o app com o pad tocando:** nada continua soando. → Task 9.
